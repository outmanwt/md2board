# md2board 规格源契约 (Spec-Driven Contract)

md2board 遵循「Markdown 唯一事实来源（Single Source of Truth）」的原则。整个工作台所有的层级导航、全局脉冲、进度统计、验收回写和代码快照均由一份标准结构化 Markdown 派生。

---

## 1. 结构化层级定义

md2board 严格映射 Markdown 的四级标题体系：

| 层级 | Markdown 语法 | 概念角色 | UI 呈现形式 |
| :--- | :--- | :--- | :--- |
| **Level 1** | `# 项目名称` | 项目总目标与全局上下文 | 顶层大标题、全局脉冲圆环 (Global Pulse) 与阶段总览 |
| **Level 2** | `## 阶段名称` | 顶层里程碑阶段 (Phase) | 航线轴 (Phase Axis) 与阶段大卡片 |
| **Level 3** | `### 章节名称` | 架构与领域章节 (Chapter) | 章节卡片网格，承载业务模块 |
| **Level 4** | `#### 小节名称` | 原子执行小节 (Section) | 左右分栏工作台：验收清单 + 增量 Diff 快照 |

> [!TIP]
> **目标引用语法 (`> 引用文案`)**：
> 紧随任何级别标题后的 `> 文案` 会自动挂载为该节点的说明目标（Goal）。
> 例如：
> ```markdown
> ## Foundation & Context
> > 建立规范驱动的项目基座，让所有后续实现都围绕同一份事实来源展开。
> ```

---

## 2. 验收项与就地回写契约

- **语法格式**：
  ```markdown
  - [x] 已完成的验收条目
  - [ ] 待完成或进行中的验收条目
  ```
- **核心原则**：
  1. **原子验收项是唯一可写字段**：进度的百分比只做纯函数派生，不可人为手写。
  2. **空小节安全退出加权**：若某个规划中的小节没有任何 `- [ ]` 条目，它在进度加权中返回空，不会将整体进度稀释为 0。
  3. **双向源码绑定**：用户在 Level 4 界面上点击复选框，md2board 内部依据行号直接修改 Markdown 文本（`- [ ]` 与 `- [x]` 互转，保留行首缩进），并触发实时进度波。
  4. **落盘出口**：界面回写只进浏览器缓存（缓存按规格内容哈希隔离，多个看板互不覆盖）；要同步回磁盘源文件，在规格编辑器（快捷键 `M`）中点「导出 .md」下载最新内容并覆盖原文件。

---

## 3. 代码块处理规则

- **`diff` 代码块**：在任何 `#### 小节` 下嵌入标准 `diff` 代码块，作为该小节的增量快照：

````markdown
#### Parser Contract
> 解析四级结构与验收清单。
- [x] 识别标题
- [ ] 支持行号映射

```diff
+ parseHeading(line, depth)
- legacyParser()
@@ hunk headers @@
```
````

- 以 `+` 开头的行渲染为翡翠绿（Add）
- 以 `-` 开头的行渲染为玫瑰粉红（Del）
- 以 `@@` 开头的行渲染为天青色（Hunk header）
- 其余行作为普通上下文代码高亮展示

- **其他代码块**：`bash`、`json`、`go` 等非 `diff` 代码块会被解析器**整体忽略**——块内的 `#` 标题、`##` 标题、`- [ ]` 清单都不会进入层级或验收统计。可放心在规格中粘贴任意代码示例。

---

## 4. 标题自动去重规则

md2board 内置标题清洗器：
如果 Markdown 写作 `#### 01. 需求定义`、`#### 1-1 需求定义`、`#### 2.3 需求定义` 或 `#### 1、需求定义`，解析引擎会自动识别并提取纯文本 `需求定义`，避免与界面上自动生成的序号徽章（如 `01 01 需求定义`）发生重复。支持「数字 + 分隔符」的多级编号组合。
